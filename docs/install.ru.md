Для работы с мостом требуется:

- **1C:EDT** с открытым проектом – либо позвольте `edt-bridge-mcp` поднять headless EDT.
- Установленная локально **платформа 1С:Предприятие**, совместимая с версией проекта. Она нужна для
  `edt_dump_external_object` (сборка `.epf` и `.erf`) и для `edt_update_infobase`: EDT управляет
  этой платформой, когда компилирует бинарник и обновляет информационную базу.

Для сборки плагина из исходников требуется:

- **JDK под бандлы EDT**. EDT 2026.2 поставляется с class-файлами Java 25, поэтому для компиляции
  против них нужен JDK 25. Скрипт сборки определяет уровень по пулу и сам находит подходящий JDK, в
  том числе установленный рядом с EDT. Байткод jar по-прежнему нацелен на Java 17, поэтому одна
  сборка грузится и в версиях EDT, работающих на Java 17.
- Локальный **пул бандлов EDT**. На **Windows** это p2-пул `%USERPROFILE%\.p2\pool\plugins`. На
  **macOS** он лежит внутри установленного компонента:
  `.../1C/1CE/components/1c-edt-<ver>-x86_64/1cedt (<ver>).app/Contents/Eclipse/plugins`, и
  shell-сборка находит его сама.

## Установка вручную (без обвязки)

Обвязка устанавливает jar и запускает EDT. Для установки и запуска плагина вручную:

1. Скачать jar со [страницы Releases](https://github.com/keyfire/edt-bridge/releases), где также
   находится `SHA256SUMS.txt`, или собрать его, как описано ниже.
2. Скопировать jar в `dropins/` EDT: на Windows `.../installations/<EDT>/1cedt/dropins/`, на **macOS**
   `.../1c-edt-<ver>-x86_64/1cedt (<ver>).app/Contents/Eclipse/dropins/`, создав папку, если ее нет.
   Оставить только один jar EDT-Bridge: при наличии двух файлов Equinox может загрузить любой из них.
3. **Перезапустить EDT.** Плагин запускает MCP-сервер на `http://127.0.0.1:8770/mcp` или на
   следующем свободном порту, если 8770 занят.

Запустить EDT **headless**, без окна: `scripts/run-headless.ps1 -Workspace <ws>` на Windows либо
`scripts/run-headless.sh --workspace <ws>` на macOS и Linux. `scripts/toggle-headless.ps1` включает
и выключает его одним действием, а запущенную EDT с интерфейсом это никогда не трогает. Запустить
**интерфейс** на рабочей области: `scripts/run-gui.ps1 -Workspace <ws>`.

Оба скрипта не запускают вторую EDT на занятой рабочей области и не снимают блокировку
работающего экземпляра. Общая проверка находится в `scripts/edt-common.ps1`. При запуске `1cedt.exe` вручную проверка не выполняется. Второй экземпляр завершится с сообщением
"рабочая область уже используется". Повторные попытки могут оставить не полностью запущенные окна.

MCP-клиент может обращаться к плагину напрямую по HTTP. Добавить
`{ "edt-bridge": { "type": "http", "url": "http://127.0.0.1:8770/mcp" } }` в его `.mcp.json`. Сервер использует JSON-RPC по HTTP: `initialize`, `tools/list`, `tools/call`.

## Переменные окружения

Настройки у обвязки и у плагина называются одинаково, `EDT_BRIDGE_*`, но читают их разные стороны:
обвязка при своем запуске, плагин внутри EDT. У большинства настроек обвязки есть флаг-двойник, он
описан в [Командах](/ru/cli).

**Читает обвязка `edt-bridge-mcp`**

| Переменная | Флаг | По умолчанию | Что задает |
|------------|------|--------------|------------|
| `EDT_BRIDGE_PORT` | `--port` | `8770` | порт, на котором обвязка ищет мост |
| `EDT_BRIDGE_PORT_SCAN` | – | `20` | сколько портов подряд начиная с этого просматривать. Занятый порт плагин отдает следующему свободному, и в этом же окне мост потом ищется |
| `EDT_BRIDGE_TOKEN` | – | пусто | токен инструментов записи. Передается в заголовке `Authorization: Bearer` и передается в JVM headless-экземпляра |
| `EDT_BRIDGE_WORKSPACE` | `--workspace` | – | рабочая область EDT для автоматического запуска headless |
| `EDT_BRIDGE_EDT_DIR` | `--edt-dir` | самая свежая установка | каталог установки EDT (`.../1cedt`) |
| `EDT_BRIDGE_START_TIMEOUT` | `--start-timeout` | `360` | сколько секунд ожидать запуск моста |
| `EDT_BRIDGE_AUTOSTART` | `--no-autostart` | включен | `0` – не запускать EDT и только пересылать запросы |
| `EDT_BRIDGE_WINDOW_WAIT` | – | `90` | сколько секунд команда `gui` ждет появления окна EDT. Загрузка большой рабочей области может занять несколько минут; если окно не появилось, команду можно повторить |
| `EDT_BRIDGE_LANG` | – | язык системы | язык справки и сообщений обвязки (`ru` или `en`) |
| `EDT_BRIDGE_NO_PLUGINS` | – | выкл | `1` – не искать [плагины обвязки](#плагины-обвязки), оставить только штатные возможности |
| `EDT_BRIDGE_PLUGIN_INDEX` | – | – | адрес реестра пакетов, который `self-update` передает pip для плагинов, установленных по имени проекта. У плагина, поставленного из git, источник свой |

**Читает плагин внутри EDT**

| Переменная | Свойство запуска | По умолчанию | Что задает |
|------------|------------------|--------------|------------|
| `EDT_BRIDGE_PORT` | `-Dedt.bridge.port` | `8770` | порт MCP-сервера. Если он занят, берется следующий свободный |
| `EDT_BRIDGE_TOKEN` | `-Dedt.bridge.token` | со страницы параметров | общий секрет, который требует каждый инструмент записи |
| `EDT_BRIDGE_ALLOW_EVALUATE` | – | выключено | `1` разрешает `edt_evaluate` – исполнение произвольного BSL против живой информационной базы. То же самое включается на странице параметров |
| `EDT_BRIDGE_AGENT_IDLE_MINUTES` | `-Dedt.bridge.agent-idle-minutes` | `30` | через сколько минут простоя агент конфигуратора останавливается сам. `off` – держать вечно |

Переменные окружения и свойства `-Dedt.bridge.*`, заданные при запуске, имеют приоритет над
сохраненными параметрами EDT. Обвязка использует их для управления headless EDT.


При автоматическом запуске отдельный процесс-наблюдатель держит ввод CLI открытым и отслеживает
запущенный `1cedtcli`. Если CLI завершается до готовности моста, обвязка возвращает код завершения
и до 16 КиБ из конца объединенного stdout/stderr. Вывод декодируется как UTF-8 с заменой
некорректных байтов. Наблюдатель завершается вместе с CLI; следующий вызов может повторить запуск.
`--start-timeout` ограничивает ожидание готовности, пока CLI работает. По таймауту работающий
процесс остается запущенным; EDT также продолжает работу после завершения короткой команды обвязки.

### Сборка из исходников

Без Maven получается быстрее всего: локальный JDK плюс пул EDT, сеть не нужна.

```powershell
# Windows – по умолчанию: -Pool %USERPROFILE%\.p2\pool\plugins, -JdkHome %JAVA_HOME%
powershell -ExecutionPolicy Bypass -File scripts/build-nomaven.ps1
```

```bash
# macOS / Linux – --pool автоопределяется из пула установленного 1C:EDT
./scripts/build-nomaven.sh
```

На выходе `build/io.github.keyfire.edtbridge_<версия>.<таймстамп>.jar`. Maven и Tycho
(`mvn -f pom.xml clean verify`, сначала правьте `edt-bridge.target`) остаются для CI.

Релизы собираются из локально построенного jar, потому что CI его скомпилировать не может:
SDK-бандлы 1C:EDT проприетарны и анонимно не скачиваются. Сопровождающий запускает
`scripts/build-nomaven.ps1 -Dist`, размещает jar в `dist/`, ставит тег `vX.Y.Z` и отправляет тег в
репозиторий. `.github/workflows/release.yml` прикладывает jar и контрольную сумму. Проверить
приложенный файл можно так: пересобрать из тегированного исходника и сравнить.

## Плагины обвязки

Плагины обвязки поставляются отдельными пакетами и устанавливаются в ее окружение. Они могут
содержать, например, справочные материалы под чужой лицензией или инструменты внутренних сервисов.
Обвязка находит плагины через группу точек расширения `edt_bridge.tools`, добавляет их инструменты
к своему списку и выполняет их. Эти инструменты доступны и без запущенной EDT.

Установка:

```bash
pipx inject edt-bridge-mcp <пакет>
```

### Когда pipx работает поверх uv (pipx >= 1.15)

При использовании uv pipx создает окружение без pip. Учитывать следующие особенности:

- При записи `--pip-args="--no-deps"` аргумент передается в uv в разобранном виде, и uv выводит
  справку об использовании. Передать флаг отдельным аргументом:
  `pipx inject edt-bridge-mcp <пакет> --pip-args "--no-deps"`.
- `<venv>/Scripts/python -m pip` возвращает "No module named pip". Для работы с окружением
  использовать `pipx runpip edt-bridge-mcp`: эта команда обращается к `uv pip`.
- Переустановка плагина без `--no-deps` переустанавливает и ядро. Если `edt-bridge-mcp.exe` занят
  действующей MCP-сессией, заменить файл не удается ("failed to persist ... Отказано в доступе").
  Сам плагин обычно успевает установиться. Результат проверить командой `edt-bridge-mcp plugins`,
  а не по коду выхода.

Для обновления плагина без переустановки занятого ядра выполнить:

```bash
python -m pipx runpip edt-bridge-mcp -- install --upgrade --no-deps <пакет>
```

Для плагина из закрытого реестра добавить `--index-url <адрес индекса>`.

`edt-bridge-mcp self-update` обновляет установленные плагины; параметр `--plugins-only`
ограничивает обновление плагинами. Каждый плагин обновляется из источника установки:
git-репозитория либо реестра пакетов по имени проекта. Адрес реестра задает переменная
`EDT_BRIDGE_PLUGIN_INDEX`.

`edt-bridge-mcp plugins` показывает подключенные пакеты, точки расширения и добавленные ими
инструменты. Если загрузить плагин не удалось, команда выводит сообщение загрузчика. `EDT_BRIDGE_NO_PLUGINS=1`
выключает поиск плагинов.

Плагин объявляет инструменты в `pyproject.toml`:

```toml
[project.entry-points."edt_bridge.tools"]
package-name = "my_package.tools:tools"
```

Значение – это `Tool` из `edt_bridge_mcp.plugins`, их список либо функция без аргументов,
возвращающая то или другое. `Tool` содержит дескриптор MCP – `name`, `description`, JSON-схему
аргументов – и обработчик, который вызывает обвязка. Строка становится текстовым результатом, любое
другое JSON-сериализуемое значение печатается как JSON, а исключение – сообщением об ошибке
инструмента. Ошибка точки расширения, повтор имени инструмента и совпадение имени с инструментом обвязки
приводят к сообщению об ошибке.

Обработчик, объявивший еще и параметр `bridge` – `handler(arguments, bridge)`, – получает функцию
`bridge(имя_инструмента, аргументы) -> str`: она отправляет один вызов живому мосту и возвращает
текст его результата. Этот вызов не запускает EDT. Если мост не работает, функция вызывает
`RuntimeError` с сообщением, которое возвращается как результат плагина. Старые версии обвязки вызывают обработчик с одним
аргументом, поэтому следует задать для `bridge` значение по умолчанию `None`.
