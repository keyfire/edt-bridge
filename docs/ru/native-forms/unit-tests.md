`edt-bridge-mcp unit-tests` и инструмент обвязки `edt_unit_tests` выполняют тесты
[YAXUnit](https://github.com/bia-technologies/yaxunit) собранных расширений конфигурации.
Модульный тест проверяет логику под формой без интерфейса, быстрее и точнее сценария формы.

Запуск копирует `1Cv8.1CD` выбранной тестовой базы, загружает в копию указанные файлы `.cfe`
через `ibcmd` и запускает клиент 1С:Предприятия на отдельном экране Xvfb с
`/C RunUnitTests=<файл>`. YAXUnit выполняет тесты этих расширений, записывает отчет jUnit и
закрывает клиент. Сама тестовая база не меняется.

## Подготовка тестовой базы

Нужно то же окружение, что и для [проверки форм](/ru/native-forms): изолированный Linux,
установка платформы с `1cv8` и `ibcmd`, лицензия платформы, `Xvfb` и `libX11`. Кроме того, в
тестовую базу один раз загружается YAXUnit как расширение `YAXUNIT`. Возьмите
`YAxUnit-<версия>.cfe` из [выпусков YAXUnit](https://github.com/bia-technologies/yaxunit/releases)
и загрузите его:

```bash
ibcmd config load --db-path=/srv/test-bases/orders --extension=YAXUNIT YAxUnit-25.12.cfe
ibcmd config apply --db-path=/srv/test-bases/orders --extension=YAXUNIT --force
```

Безопасный режим и защиту от опасных действий у `YAXUNIT` запуск снимает в своей копии, в самой
базе их можно оставить как есть. `edt_unit_tests` берет базу, платформу и пользователя из
`EDT_BRIDGE_TEST_INFOBASE`, `EDT_BRIDGE_TEST_PLATFORM` и `EDT_BRIDGE_TEST_USER`, тех же
[переменных](/ru/settings), что и `edt_test_form`.

## Расширения и отбор

- `--extension ИМЯ=ПУТЬ` (в инструменте – `extensions`, список `{path, name}`) загружается в копию
  в указанном порядке: расширение с тестовыми модулями и, если проверяемый код в отдельном
  расширении, оно тоже. `ИМЯ` – имя расширения в его проекте: `ibcmd` дает загруженному
  расширению имя, записанное в файле, и другое `ИМЯ` завершает запуск со статусом
  `extension_name_mismatch`.
- Загруженные расширения работают со снятыми безопасным режимом и защитой от опасных действий.
- `--module` и `--test` (в инструменте – `modules` и `tests`) сужают запуск. Тест называется
  `Модуль.Тест` или `Модуль.Тест.Контекст`, например `ОМ_Заказы.СуммаЗаказа.Сервер`. Без них
  выполняются все тесты загруженных расширений.

Тестовый модуль – общий модуль расширения с экспортной процедурой `ИсполняемыеСценарии`, которая
регистрирует тесты:

```bsl
Процедура ИсполняемыеСценарии() Экспорт
	ЮТТесты.ДобавитьТест("СуммаЗаказа");
КонецПроцедуры

Процедура СуммаЗаказа() Экспорт
	ЮТест.ОжидаетЧто(Заказы.СуммаЗаказа(2, 3)).Равно(5);
КонецПроцедуры
```

Вызов инструмента, который выполняет один этот тест:

```json
{"extensions": [{"path": "/work/out/tests.cfe", "name": "tests"}],
 "tests": ["ОМ_Заказы.СуммаЗаказа"]}
```

## Результат

Команда записывает в `--output-dir` файл `result.json`, отчеты YAXUnit `junit.xml` и
`allure-results/` и его лог `yaxunit.log`; инструмент отвечает объектом из `result.json`. Оба
отчета пишет сам YAXUnit: `junit.xml` отдается GitLab как `artifacts:reports:junit`, а
`allure-results/` – в `allure generate`, так же как [отчеты проверки формы](/ru/native-forms/results#отчеты-для-ci).

| Поле | Содержимое |
|------|------------|
| `status` | итог, см. ниже |
| `summary` | число тестов, прошедших, упавших, ошибок и пропущенных |
| `tests` | каждый тест: `module`, `name`, `context`, `extension`, `status` (`passed`, `failed`, `error`, `skipped`), `time` в секундах, `message`, `expected`, `actual` и `trace` |
| `yaxunitErrors` | записи об ошибках из лога YAXUnit |
| `eventLog.errors` | ошибки, записанные платформой в журнал регистрации копии за время запуска, с модулем и строкой |
| `yaxunitVersion` | версия YAXUnit, выполнившая тесты |
| `piiFilter` | если задана `EDT_BRIDGE_PII`, режим и число замен в ответе и файлах; см. [Персональные данные](/ru/personal-data) |
| `filesWithheld` | при включенном фильтре – сколько файлов запуска удалено, потому что фильтр не умеет их прочитать, например приложенная тестом картинка |

`trace` содержит строки проверяемого кода без кадров самого YAXUnit. `failed` – не выполнившееся
утверждение, `error` – исключение в тесте или в проверяемом коде. Если тестов больше 500, список
начинается с упавших, а `testsListed` называет его длину.

| `status` | Значение |
|----------|----------|
| `passed` | выполнен хотя бы один тест, и ни один не упал |
| `failed` | упал тест, или YAXUnit сообщил об ошибке вне тестов |
| `no_tests` | отбор не выбрал ни одного теста |
| `yaxunit_failed` | YAXUnit остановился до отчета; причина в `yaxunitErrors`, например тестовый модуль не компилируется |
| `yaxunit_missing` | в тестовой базе нет расширения `YAXUNIT` |
| `extension_load_failed` | `ibcmd` не загрузил или не применил расширение; `error` приводит его текст |
| `extension_name_mismatch` | в файле расширение с другим именем |
| `timeout` | запуск исчерпал предел времени; `screenshot` показывает, чего ждал клиент |
| `license_unavailable`, `access_denied` | платформа отказалась запускать клиент |
| `pii_filter_failed` | фильтр персональных данных завершился ошибкой; ответ скрыт, каталог вывода очищен |

Код возврата команды: **0** для `passed`, **1** для отклоненного вызова и **2** в остальных случаях.
