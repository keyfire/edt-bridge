Плагины обвязки поставляются отдельными пакетами и устанавливаются в ее окружение. Они могут
содержать, например, справочные материалы под чужой лицензией или инструменты внутренних сервисов.
Обвязка находит плагины через группу точек расширения `edt_bridge.tools`, добавляет их инструменты
к своему списку и выполняет их. Эти инструменты доступны и без запущенной EDT.

Установка:

```bash
pipx inject edt-bridge-mcp <пакет>
```

## Когда pipx работает поверх uv (pipx >= 1.15)

При использовании uv pipx создает окружение без pip. Учитывать следующие особенности:

- При записи `--pip-args="--no-deps"` аргумент передается в uv в разобранном виде, и uv выводит
  справку об использовании. Передать флаг отдельным аргументом:
  `pipx inject edt-bridge-mcp <пакет> --pip-args "--no-deps"`.
- `<venv>/Scripts/python -m pip` возвращает "No module named pip". Для работы с окружением
  использовать `pipx runpip edt-bridge-mcp`: эта команда обращается к `uv pip`.
- Переустановка плагина без `--no-deps` переустанавливает и ядро. Если `edt-bridge-mcp.exe` занят
  действующей MCP-сессией, заменить файл не удается ("failed to persist ... Отказано в доступе").
  Сам плагин обычно успевает установиться. Результат проверить командой `edt-bridge-mcp plugins`,
  а не по коду выхода.

Для обновления плагина без переустановки занятого ядра выполнить:

```bash
python -m pipx runpip edt-bridge-mcp -- install --upgrade --no-deps <пакет>
```

Для плагина из закрытого реестра добавить `--index-url <адрес индекса>`.

## Обновление и список плагинов

`edt-bridge-mcp self-update` обновляет установленные плагины; параметр `--plugins-only`
ограничивает обновление плагинами. Каждый плагин обновляется из источника установки:
git-репозитория либо реестра пакетов по имени проекта. Адрес реестра задает переменная
`EDT_BRIDGE_PLUGIN_INDEX`.

`edt-bridge-mcp plugins` показывает подключенные пакеты, точки расширения и добавленные ими
инструменты. Если загрузить плагин не удалось, команда выводит сообщение загрузчика. `EDT_BRIDGE_NO_PLUGINS=1`
выключает поиск плагинов.

## Объявление инструментов

Плагин объявляет инструменты в `pyproject.toml`:

```toml
[project.entry-points."edt_bridge.tools"]
package-name = "my_package.tools:tools"
```

Значение – это `Tool` из `edt_bridge_mcp.plugins`, их список либо функция без аргументов,
возвращающая то или другое. `Tool` содержит дескриптор MCP – `name`, `description`, JSON-схему
аргументов – и обработчик, который вызывает обвязка. Строка становится текстовым результатом, любое
другое JSON-сериализуемое значение печатается как JSON, а исключение – сообщением об ошибке
инструмента. Ошибка точки расширения, повтор имени инструмента и совпадение имени с инструментом обвязки
приводят к сообщению об ошибке.

Обработчик, объявивший еще и параметр `bridge` – `handler(arguments, bridge)`, – получает функцию
`bridge(имя_инструмента, аргументы) -> str`: она отправляет один вызов живому мосту и возвращает
текст его результата. Этот вызов не запускает EDT. Если мост не работает, функция вызывает
`RuntimeError` с сообщением, которое возвращается как результат плагина. Старые версии обвязки вызывают обработчик с одним
аргументом, поэтому следует задать для `bridge` значение по умолчанию `None`.
