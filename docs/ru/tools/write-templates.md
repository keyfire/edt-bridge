Эти инструменты создают макеты и заменяют их содержимое: HTML-макеты и текстовые макеты,
схемы компоновки данных и табличные документы.

Для записи нужен токен; без `apply=true` инструмент возвращает план. Общие правила приведены
в разделе [План и применение](/ru/tools#план-и-применение).

| Инструмент записи | Что делает |
|-------------------|------------|
| `edt_replace_html_template` | Заменяет полный точный текст существующей языковой версии HTML-макета. Предпросмотр возвращает старый и новый текст и хеши. Для записи нужны `expectedHash`, `force=true`, `apply=true` и токен. Несохраненные редакторы, измененная карта языков, устаревшие ресурсы, запрет записи и некорректный UTF-8 дают отказ. Другие языки сохраняются. Если проект занят другой операцией EDT, например обновлением базы, которое ждет ответа на вопрос, запись не выполняется и ответ содержит `busy=true`; вызов следует повторить после завершения этой операции. |
| `edt_add_template` | Создает макет у отчета, внешнего отчета, обработки или другого объекта: схему компоновки данных с пустой схемой или, с `templateType=SpreadsheetDocument`, пустой макет печатной формы; `setMainSchema` назначает его основной схемой отчета, и клиент открывает отчет общей формой отчета конфигурации. `templateType=HTMLDocument` создает HTML-макет с одной страницей, а `TextDocument` – текстовый макет; оба берут начальный текст из `text`. По умолчанию предпросмотр, для записи нужен токен; запись ждет, пока EDT создаст файл содержимого, и возвращает его `sourceHash` для первой записи. |
| `edt_write_spreadsheet` | Заменяет весь макет переданными колонками и областями. Макет с возможностями, которых нет в описании, отклоняется без `dropUnsupported=true`. Предпросмотр возвращает изменение и `sourceHash`; для записи нужны он же в `expectedHash` и токен. |
| `edt_replace_dcs` | Заменяет полный текст схемы; EDT перечитывает схему из файла. Предпросмотр возвращает старый и новый текст и хеши; для записи нужны `expectedHash`, `force=true` и токен. Сразу после `edt_add_template` файл схемы, который EDT еще не записала, ожидается до 15 с. Предпросмотр и запись сначала проверяют схему. Текст, который EDT не прочитает, отклоняется со строкой и колонкой, где останавливается чтение: EDT оставил бы прежнюю схему с ее замечаниями и собрал бы ее. `problems` называет набор данных без источника и вариант настроек без структуры, а `valid` ложно, пока есть ошибка. После записи `revalidated` говорит, принял ли EDT схему и проверил ли ее. Остальное в формате платформы проверяет сборка `edt_dump_external_object`. |
| `edt_modify_dcs` | Меняет часть схемы без передачи всего XML. `edits`: `addField` (`dataSet`, `dataPath`, `titleRu`), `addParameter` (`name`, `titleRu`, `type`: String(N), Number(D,F), Date, DateTime, Boolean, StandardPeriod), `setQuery` (`dataSet`, `query`), `replaceFragment` (`fragment`, `replacement`: точный фрагмент текста, который возвращает `edt_read_dcs`; отказ, если он не найден или найден несколько раз), `setField` (`dataSet`, `dataPath`, `titleRu` и/или `format`, например `ЧДЦ=2`), `removeField` (`dataSet`, `dataPath`). Остальная часть файла не меняется, повтор отклоняется. Ответ называет измененные строки и `resultHash` без текста схемы. Для записи `expectedHash` – `sourceHash` из `edt_read_dcs` или предпросмотра. Измененная схема проверяется так же, как в `edt_replace_dcs`: текст, который EDT не прочитает, не записывается, а `problems` называет набор без источника и вариант без структуры. |

## Создание HTML-макета и текстового макета

`edt_add_template` с `templateType=HTMLDocument` (синоним `HTMLДокумент`) создает HTML-макет с
одной страницей. Страница создается на языке, на котором EDT редактирует проект; ответ сообщает
его в `language`. EDT хранит список страниц в `Template.htmldoc`, а каждую страницу – в файле с
именем ее языка, например `ru.html`. `TextDocument` (синоним `ТекстовыйДокумент`) создает
текстовый макет, содержимое которого – файл `Template.txt`.

`text` – начальный текст страницы или текстового макета, он записывается точно в переданном
виде. Без него текст пустой, а для схемы и табличного макета параметр отклоняется. После
`apply=true` поле `contentPath` называет файл. У HTML-макета `sourceHash` служит
`expectedHash` первого вызова `edt_replace_html_template`. Отдельного инструмента для изменения
текстового макета нет: его текст – файл из `contentPath`, и EDT читает его как есть. Другие
страницы HTML-макета и общие макеты этот инструмент не создает.

Например, страница справки обработки:

```json
{
  "projectName": "Demo",
  "ownerFqn": "DataProcessor.Подписки",
  "name": "Справка",
  "templateType": "HTMLDocument",
  "text": "<html><body><p>Как заполнить заявку</p></body></html>"
}
```

## Замена HTML-макета

Перед заменой прочитать нужную языковую версию HTML. Хеш охватывает точные UTF-8 байты:
BOM представлен начальным символом U+FEFF в `text`. Для сохранения BOM включить этот символ
в новый текст. Переводы строк и конечные пробелы записываются как переданы. Пустая строка
намеренно очищает языковую версию; отсутствие текста дает отказ. При совпадении текста
запись не выполняется. Редакторы затронутого макета нужно сохранить.
