Эти инструменты создают, импортируют, очищают и удаляют проекты, собирают файлы `.cfe`,
`.epf` и `.erf`, редактируют свойства и управляют приложениями EDT.

Для записи нужен токен; без `apply=true` инструмент возвращает план. Общие правила приведены
в разделе [План и применение](/ru/tools#план-и-применение).

| Инструмент записи | Что делает |
|-------------------|------------|
| `edt_import_project` | Регистрирует существующий каталог проекта EDT или создает проект из конфигурации 1С:Предприятия. При регистрации файлы остаются в прежнем каталоге. Повторное открытие зарегистрированного проекта сохраняет его настройки и связи с базами. |
| `edt_applications` | Список штатных приложений открытого проекта (`action=list`). Действие `associate` связывает проект с зарегистрированной базой по точному имени или UUID и использует существующее приложение. База не обновляется. Действие `start` запускает тонкий клиент приложения информационной базы, `stop` использует его id из списка; по умолчанию возвращают план, для записи нужен токен. Остановка ограничена процессом, дескриптор которого вернулся этому мосту. Если процесс еще завершается, повторное чтение `bridgeSession` через `list` подтверждает завершение. |
| `edt_create_extension` · `edt_create_external_object` | Создают проект расширения конфигурации или внешнего объекта. Расширение использует `IExtensionProjectManager`: корневая Configuration заимствуется из базовой конфигурации, как в мастере EDT; задаются префикс имен, назначение и синоним. Параметр `kind` инструмента `edt_create_external_object` принимает `processor` (по умолчанию) или `report`; при необходимости указать `baseProjectName`. Dry-run возвращает тип объекта и FQN, apply создает проект через `IExternalObjectProjectManager`. Добавить управляемую форму и собрать `.epf` или `.erf` через `edt_dump_external_object`. |
| `edt_modify_external_object` | Меняет русский синоним, комментарий или основную форму существующей внешней обработки или отчета. Для отчета также можно выбрать формы настроек и варианта и основную схему компоновки данных. |
| `edt_modify_extension` | Меняет синоним на языке по умолчанию, комментарий, поставщика, версию, префикс имен или назначение существующего расширения в EDT. |
| `edt_clean_project` · `edt_delete_project` | Очищают результаты сборки или удаляют проект. Очистка программно вызывает функцию "Очистить" EDT, возвращает число замечаний до и после и ожидает стабилизации счетчика, чтобы проверки выполнились заново. Для одного модуля, измененного на диске, можно использовать `edt_project_errors` с `refresh=true`. Удаление выполняется средствами рабочей области Eclipse и требует `force`, поскольку отменить его нельзя. |
| `edt_build_extension` · `edt_dump_external_object` | Собирает бинарники: `.cfe` из проекта расширения, `.epf` или `.erf` из внешней обработки или отчета. Оба инструмента могут использовать полную установку платформы, если EDT не находит толстый клиент. Тогда модель выгружается в XML конфигуратора прямо в процессе, а файл собирается полной установкой 1С с диска во временной базе, которая потом удаляется, или в копии базы из `EDT_BRIDGE_DUMP_INFOBASE`; расширению с заимствованной формой, исключившей Post или Write, нужна эта копия: такие команды разрешает только базовая конфигурация. `logPath` сохраняет журнал сборки платформы рядом с артефактом. Пустой табличный макет выгружается пустым документом в том виде, в каком его пишет конфигуратор; `method` называет такие макеты. При отказе штатного дампера используется дисковый маршрут; `route` задает маршрут явно: `edt` или `disk`. Если отказ отключил автогенерацию выгрузок, она восстанавливается. Успешная сборка называет маршрут в `method` и не повторяет отказ штатного дампера; неудачная сохраняет его в `nativeError`. |
| `edt_import_external_object` | Импортирует существующую `.epf` или `.erf` в новый проект EDT, при необходимости с `baseProjectName`. Распаковывает XML через EDT или полную установку платформы и передает штатному импортеру EDT. Сохраняет исходный файл; при ошибке удаляет собственный незавершенный проект. |

## Импорт конфигурации

Задайте `mode=configuration`, имя нового проекта в `name` и путь к каталогу
с `Configuration.xml` или к файлу `.cf`. EDT создаст проект в текущей рабочей
области. Для извлечения конфигурации из `.cf` во временные файлы XML нужен
совместимый локальный толстый клиент 1С:Предприятия. Для создания проекта
передайте `apply=true`. Для большой конфигурации добавьте `async=true` и
проверяйте состояние импорта через `edt_job_status`.

## Редактирование свойств проекта

Вызовите `edt_property_reference` с именем проекта и FQN корневого объекта, например
`ExternalReport.Summary` для внешнего отчета или `Configuration` для расширения.
Ответ содержит текущие значения и список доступных форм или макетов для ссылочных свойств.

Для внешнего объекта передайте `projectName`, `fqn` и нужные свойства. Форму или макет
можно указать по имени, например `SummaryForm`, или по полному FQN. Выбрать можно
управляемую форму самого объекта. Основная схема компоновки должна быть макетом
этого типа в том же отчете.

Для расширения передайте `projectName` и нужные свойства. `purpose` принимает
`Customization`, `AddOn` или `Patch`. `version` задает версию самого расширения.
Параметры регистрации в информационной базе доступны через `edt_extension_properties`.

Оба инструмента проверяют весь запрос и возвращают `changes` со значениями `before` и
`after`. Для сохранения повторите вызов с `apply=true`. `serialized` подтверждает запись
модели в файлы проекта.

## Связь приложения с базой

Связь приложения создается в текущем контексте EDT, включая ветку Git.
`associationVerified` подтверждает сохраненную связь, `verified` – штатное приложение.
Повторный вызов использует это приложение и не обновляет базу.

## Полная очистка

При полной очистке проверять `stage`, `completedStages`, время и сведения об отмене и статусе.
`ok=false` с `applied=true` обозначает последующий отказ после изменения состояния сборки. Снимок
заданий сам по себе не доказывает причину отмены.
