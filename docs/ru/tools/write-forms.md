Эти инструменты добавляют управляемые формы и изменяют их реквизиты, команды, обработчики
событий и элементы. `edt_form_identifiers` проверяет визуальные ID формы и перенумеровывает
повторные вхождения.

Для записи нужен токен; без `apply=true` инструмент возвращает план. Общие правила приведены
в разделе [План и применение](/ru/tools#план-и-применение).

| Инструмент записи | Что делает |
|-------------------|------------|
| `edt_add_form` | Добавляет объекту метаданных управляемую форму штатным генератором EDT – тем же, что стоит за мастером "Новая форма". Генератор создает форму, ее элементы и модуль в XML. Для `DataProcessor` и `ExternalDataProcessor` опущенный `formType` выбирает `OBJECT` (синоним `ФормаОбработки`) с основным реквизитом `Объект`; для пустой формы передайте `GENERIC`. При `defaultForm=true` вид формы определяет основное свойство, например `defaultObjectForm` или `defaultFolderForm` справочника. Неподдерживаемое назначение отклоняется до создания. `defaultForm` подтверждает выполненное назначение, `defaultFormProperty` указывает свойство. |
| `edt_add_form_attribute` · `edt_modify_form_attribute` · `edt_remove_form_attribute` | Добавляет, меняет и удаляет реквизит формы, а с параметром `columnOf` – колонку реквизита типа ТаблицаЗначений. Идентификаторы выдает служба идентификаторов формы. Параметр `main=true` в `edt_add_form_attribute` отмечает реквизит основным (не сочетается с `columnOf`). Кроме грамматики типов метаданных принимаются платформенные типы, допустимые у формы (`ТаблицаЗначений`, `СписокЗначений` и другие), и объектные типы `ВнешняяОбработкаОбъект.X` и `СправочникОбъект.X` – которые используются для основного реквизита. Удаление перечисляет связанные элементы и требует `force`. |
| `edt_add_form_command` · `edt_modify_form_command` · `edt_remove_form_command` | Добавляет, меняет и удаляет команду формы, включая `actionPurpose` (`Usual`, синоним `Normal`, `Create` или `Finish`), `associatedTable`, `currentRowUse`, `selectedRowsUse` (`Use`, `DontUse` или `Auto`) и `picture`: `StdPicture.<Имя>` платформы, `CommonPicture.<Имя>` конфигурации или `БиблиотекаКартинок.<Имя>`, пустая строка убирает картинку. При добавлении можно заодно записать в модуль формы заготовку процедуры-обработчика, а если модуля не было – создать его. Удаление перечисляет связанные кнопки и требует `force`. |
| `edt_add_form_handler` | Регистрирует обработчик события формы или ее элемента. Инструмент создает запись `handlers` в `Form.form`. Без нее платформа не вызывает процедуру, но валидация не сообщает об ошибке. Список допустимых событий берется из EDT; при неверном имени возвращается ошибка с этим списком. По запросу инструмент создает заготовку обработчика с сигнатурой события и нужной событию директивой. Для `ПриПолученииДанныхНаСервере` динамического списка заготовка получает `&НаСервереБезКонтекста` и параметры `ИмяЭлемента, Настройки, Строки`, как требует справка платформы, без параметра `Элемент`. |
| `edt_add_form_item` · `edt_modify_form_item` · `edt_remove_form_item` | Добавляет, меняет и удаляет визуальные элементы формы: поле, таблицу, кнопку, группу, декорацию. Для работы используется штатный `IFormItemManagementService`, который вызывает редактор форм. Таблица, связанная с реквизитом типа ТаблицаЗначений, получает колонки автоматически. Заданный таблице `titleRu` остается у таблицы, а сгенерированные колонки сохраняют штатный заголовок EDT. Параметр `newName` переименовывает элемент в модели формы, сохраняя имена процедур-обработчиков. Удаление включает все вложенные элементы и требует `force`. |
| `edt_form_identifiers` | Проверка визуальных ID во всей модели формы, включая подсказки, меню и командные панели. Возвращает пути повторных вхождений и хеш без выдачи ID. У реквизитов и команд отдельные пространства идентификаторов. С явным `itemPaths` показывает план перенумерации выбранных повторных вхождений. Для записи нужны текущий `expectedHash` и токен. Остальные ID, данные объектов и порядок сохраняются. Зарезервированные ID, неоднозначные числовые ссылки и открытый редактор этой формы блокируют исправление. |
| `edt_move_form_item` | Переносит существующий элемент формы по индексу или соседу с сохранением объекта, id, вложенных элементов, свойств и событий. Отклоняет циклы и переносы, требующие преобразовать вид элемента или привязку к данным. |

## Размещение элементов и списки выбора

В `edt_add_form_item` и `edt_move_form_item` можно задать ровно один способ размещения:
`index` (от нуля), `beforeItem` или `afterItem`. При переносе индекс считается без самого
переносимого элемента. Без `parent` сохраняется текущий родитель; `parent=""` выбирает корень
формы. Добавление и изменение поддерживают `groupDirection` (синоним `group`), `representation`,
`showTitle`, `united`, `titleLocation`, `maxHeight` и `verticalStretch`, если свойство применимо
к этому виду элемента. Группа колонок таблицы принимает `groupDirection` (`Horizontal`,
`Vertical` или `InCell`) и `showTitle`; EDT создает ее вертикальной. Неизвестные значения
перечислений и неприменимые свойства отклоняются.
`fieldType` задает `InputField`, `RadioButtonField` или `CheckBoxField`. `choiceList` заменяет
список выбора поля ввода или переключателя:

```json
{
  "choiceList": [
    {
      "value": "all",
      "titleRu": "Все"
    },
    {
      "value": "selected",
      "titleRu": "Выбранные"
    }
  ]
}
```

Поле, привязанное к колонке таблицы, можно поставить вне таблицы, например на панель с данными
текущей строки: передайте `edt_add_form_item` путь к данным колонки, например
`Заявки.Контрагент`, а родителем – обычную группу вне таблицы. `edt_move_form_item` не переносит
колонку через границу ее таблицы, потому что перенос изменил бы привязку к данным: удалите колонку
и добавьте поле заново.

Значение варианта может быть строкой, числом или булевым значением; ссылки и значения
перечислений не поддерживаются. Пустой список очищает варианты. `edt_form_structure` возвращает
id и свойства элементов для сверки результата. Реквизит динамического списка также содержит
`dynamicList` с `customQuery`, `mainTable` и `queryText`. Параметр `queryLimit` ограничивает каждый
запрос (по умолчанию 20000, не более 100000 символов); `queryTextTruncated` отмечает усеченный текст.

## Картинка команды

`picture` в `edt_add_form_command` и `edt_modify_form_command` принимает имена в том виде, в
каком их хранит `Form.form`: `StdPicture.Post` – стандартная картинка платформы,
`CommonPicture.Логотип` – общая картинка конфигурации. Стандартные картинки берутся из платформы
версии проекта, их можно назвать и по-русски: `БиблиотекаКартинок.Провести`, как в коде BSL,
ищется сначала среди стандартных картинок, потом среди общих и сохраняется как `StdPicture.Post`.
Неизвестная стандартная картинка отклоняется со списком похожих имен, отсутствующая общая – с ее
FQN. Пустая строка убирает картинку. Ответ и `edt_property_reference` сообщают текущую картинку в
`picture`.

## Свойства управляемой формы

При `kind=decoration` инструмент `edt_add_form_item` принимает `decorationType=Label` или
`decorationType=Picture`. Если параметр опущен, инструмент выбирает `Picture`, когда родительский
контейнер допускает этот вид. В остальных случаях используется вид, заданный EDT по умолчанию для
контейнера. Пробный вызов проверяет контейнер и возвращает `properties.decorationType`. При записи
EDT создает декорацию с соответствующим `extInfo`.

Инструменты `edt_add_form_item` и `edt_modify_form_item` принимают `fieldType=HTMLDocumentField`.
EDT создает `HtmlFieldExtInfo` и сохраняет путь к данным при изменении вида поля.
Инструмент `edt_add_form_handler` определяет событие `OnClick` (`ПриНажатии`) и штатную сигнатуру обработчика.

- Для полей доступны `width`, `height`, `horizontalStretch` и `verticalStretch`, если свойства есть в их ext-info.
- Для страниц и обычных групп `groupDirection` задает группировку элементов, а `scrollOnCompress` – прокрутку при сжатии.
- Поля ввода принимают `format` и `editFormat` как строки формата на русском языке. Пустая строка стирает русское значение и сохраняет остальные языки. Чтобы поле могло растягиваться за пределы автоматической максимальной ширины, задайте `autoMaxWidth=false` и `horizontalStretch=true`.
- Поля ввода также принимают `choiceButton`, `clearButton`, `textEdit` и `listChoiceMode`. Один `choiceList` не ограничивает ввод значений; для выбора только из списка нужен `listChoiceMode=true`.
- `choiceFoldersAndItems` задает, что можно выбрать в поле ввода со ссылкой на иерархический объект: `Auto`, `Items`, `Folders` или `FoldersAndItems`. Другие виды полей отклоняют параметр; текущее значение показывает `edt_form_structure`.
- Таблицы принимают `changeRowSet`, `autoInsertNewRow`, `changeRowOrder`, `readOnly`, `selectionMode` (`SingleRow` или `MultiRow`) и `initialTreeView` (`NoExpand`, `ExpandTopLevel` или `ExpandAllLevels`). Колонки поддерживают свойства своего поля, включая `width` и `readOnly`.
- Кнопки принимают `defaultButton` и `buttonImportance` (`Main`, `Normal` или `Supplementary`), в том числе кнопки внутри `AutoCommandBar`.
- Свойства корня управляемой формы (`autoTitle`, `showTitle`, `showCloseButton`, `allowFormCustomize`, `titleRu`, `windowOpeningMode`, `scaleVariant`, `width` и `height`) меняет `edt_modify_object` по FQN формы. Доступные имена и текущие значения возвращает `edt_property_reference`.
- `edt_form_structure` включает штатную `AutoCommandBar` и ее кнопки. Возвращенное имя панели можно передать в `parent` при добавлении или переносе кнопки. Саму штатную панель нельзя перемещать и удалять.

Карта `properties` содержит прочитанные проектные значения после записи. Код формы может переопределить их во время работы.
Набор параметров проверяется целиком до первого присваивания. Неограниченная `Строка` получает явный пустой квалификатор строки.

При создании формы `LIST` справочника или документа `edt_add_form` добавляет скрытую колонку ссылки и включает для нее свойство "Использовать всегда" динамического списка. Ссылка доступна обработчикам формы.

## Форма, измененная на диске

Форма, измененная вне EDT, например `Form.form`, исправленный вручную, попадает в модель, только
когда EDT заметит изменение и загрузит файл. Запись формы, пришедшая между этими моментами,
начиналась со старой модели, и выгрузка возвращала старую форму поверх правки. Теперь каждый
инструмент этой страницы, который меняет существующую форму, и `edt_modify_object` с FQN формы
сначала обновляют `Form.form` и ждут, пока EDT синхронизирует модель проекта с файлами.
Предпросмотр читает форму так же. Если EDT не успевает за 30 с, ничего не записывается, а
сообщение предлагает повторить вызов.

## Повторяющиеся ID формы

Для повторных ID сначала выполнить проверку, затем выбрать пути из `audit.items`.
Оставить хотя бы одно вхождение каждого повторного ID без изменения. Проверить план
с этими `itemPaths`, закрыть редактор этой формы и применить с текущим `expectedHash`.
Инструмент сбрасывает штатные кеши генераторов; такой же сброс выполняется перед добавлением
элементов, реквизитов и команд. `exportAccepted` подтверждает прием запроса на выгрузку.
Для проверки сохранения перечитать `Form.form` и повторить валидацию.
Проверка ID и ее предпросмотр не требуют токена записи.
