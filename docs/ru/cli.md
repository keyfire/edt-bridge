Обвязка `edt-bridge-mcp` работает как stdio MCP-сервер для клиента. Из командной строки можно проверить состояние моста, получить список инструментов и вызвать инструмент без запуска агента.

Без команды обвязка работает как MCP-сервер. Команды работы с мостом используют тот же экземпляр EDT. `test-form` и `unit-tests` запускают отдельные сеансы платформы.

Для вызовов инструментов код возврата **1** означает, что мост не запустился или аргументы неверны. Код **2** означает, что инструмент выполнился и вернул ошибку.

## Без команды: запуск MCP-сервера

MCP-сервер stdio для плагина edt-bridge к 1С:EDT: передает запросы в запущенную EDT и запускает headless EDT при отсутствии работающей среды.

```bash
usage: edt-bridge-mcp [опции]                   (без команды: запуск MCP-сервера)
       edt-bridge-mcp <команда> [опции]
```

**Параметры**

| Параметр | Описание |
|---|---|
| `-h, --help` | показать эту справку и выйти |
| `--workspace WORKSPACE` | рабочая область EDT для автозапуска headless |
| `--edt-dir EDT_DIR` | каталог установки EDT (папка с 1cedtcli и dropins); без флага определяется сам |
| `--port PORT` | порт моста (по умолчанию 8770) |
| `--start-timeout START_TIMEOUT` | сколько секунд ждать поднимающийся мост |
| `--no-autostart` | не поднимать headless EDT ни при каких условиях |
| `--heap HEAP` | наибольший размер кучи JVM для автозапуска headless EDT, например 4096m или 6g |
| `--vmargs OPTIONS` | другие параметры JVM для автозапуска headless EDT через пробел; присоединять к флагу знаком =, потому что они начинаются с дефиса |
| `--version` | показать версию и выйти |

**Команды**

| Команда | Описание |
|---|---|
| `call <инструмент>` | вызвать один инструмент моста и напечатать ответ |
| `tools` | перечислить инструменты запущенного моста |
| `status` | состояние моста без его запуска |
| `wait-ready` | дождаться загрузки моделей проектов |
| `shutdown` | штатно завершить EDT, обслуживающую мост |
| `gui` | остановить headless и открыть клиентскую EDT |
| `plugins` | перечислить плагины обвязки и их инструменты |
| `workspace` | упаковать, восстановить и сверить рабочую область EDT |
| `test-form` | проверить форму и результат сценария в тестовой базе |
| `unit-tests` | выполнить тесты YAXUnit расширений в копии тестовой базы |
| `self-update` | обновить jar плагина и саму обвязку |

Опции команды: edt-bridge-mcp &lt;команда&gt; `--help`. Опции подключения относятся к серверу MCP и командам работы с мостом.

## `edt-bridge-mcp call`

Вызвать один инструмент моста и напечатать результат.

```bash
usage: edt-bridge-mcp call [-h] [--json JSON | --json-file PATH | --stdin] [--raw]
                           [--workspace WORKSPACE] [--edt-dir EDT_DIR] [--port PORT]
                           [--start-timeout START_TIMEOUT] [--no-autostart] [--heap
                           HEAP] [--vmargs OPTIONS] [--version] tool
```

**Аргументы**

| Параметр | Описание |
|---|---|
| `tool` | имя инструмента, например edt_projects (перечень: edt-bridge-mcp tools) |

**Параметры**

| Параметр | Описание |
|---|---|
| `-h, --help` | показать эту справку и выйти |
| `--json JSON` | аргументы инструмента объектом JSON |
| `--json-file PATH` | читать объект JSON из файла в UTF-8; этот способ подходит для аргументов с неанглийским текстом на Windows |
| `--stdin` | читать объект JSON из потока ввода |
| `--raw` | напечатать сырой JSON-результат вместо текста, который вернул инструмент |
| `--workspace WORKSPACE` | рабочая область EDT для автозапуска headless |
| `--edt-dir EDT_DIR` | каталог установки EDT (папка с 1cedtcli и dropins); без флага определяется сам |
| `--port PORT` | порт моста (по умолчанию 8770) |
| `--start-timeout START_TIMEOUT` | сколько секунд ждать поднимающийся мост |
| `--no-autostart` | не поднимать headless EDT ни при каких условиях |
| `--heap HEAP` | наибольший размер кучи JVM для автозапуска headless EDT, например 4096m или 6g |
| `--vmargs OPTIONS` | другие параметры JVM для автозапуска headless EDT через пробел; присоединять к флагу знаком =, потому что они начинаются с дефиса |
| `--version` | показать версию и выйти |

Аргументы инструмента принимаются из `--json`, файла (`--json-file`) или потока ввода (`--stdin`). На Windows передавать кириллицу в файле: консольная кодировка может исказить аргументы командной строки.

## `edt-bridge-mcp status`

Состояние запущенного моста и версия JAR в dropins. Команда сообщает в stderr о расхождении версий обвязки и плагина. С `--all` она проверяет каждый найденный мост.

```bash
usage: edt-bridge-mcp status [-h] [--all] [--ports PORTS] [--workspace WORKSPACE]
                             [--edt-dir EDT_DIR] [--port PORT] [--start-timeout
                             START_TIMEOUT] [--no-autostart] [--heap HEAP] [--vmargs
                             OPTIONS] [--version]
```

**Параметры**

| Параметр | Описание |
|---|---|
| `-h, --help` | показать эту справку и выйти |
| `--all` | проверить все порты диапазона без фильтра рабочей области и запуска EDT |
| `--ports PORTS` | порты для `--all`, через запятую или диапазон: 8770,8772-8774 (до 128 портов) |
| `--workspace WORKSPACE` | рабочая область EDT для автозапуска headless |
| `--edt-dir EDT_DIR` | каталог установки EDT (папка с 1cedtcli и dropins); без флага определяется сам |
| `--port PORT` | порт моста (по умолчанию 8770) |
| `--start-timeout START_TIMEOUT` | сколько секунд ждать поднимающийся мост |
| `--no-autostart` | не поднимать headless EDT ни при каких условиях |
| `--heap HEAP` | наибольший размер кучи JVM для автозапуска headless EDT, например 4096m или 6g |
| `--vmargs OPTIONS` | другие параметры JVM для автозапуска headless EDT через пробел; присоединять к флагу знаком =, потому что они начинаются с дефиса |
| `--version` | показать версию и выйти |

`edt-bridge-mcp status --all` опрашивает диапазон обнаружения мостов без запуска EDT. `--ports 8770,8771` задает порты явно. Для каждого моста возвращаются workspace, порт, версия jar, версия продукта EDT и готовность проектов. Недоступные порты и другие HTTP-сервисы отмечаются отдельно от работающего моста.

## `edt-bridge-mcp wait-ready`

Дождаться загрузки моделей проектов EDT (modelReady). При необходимости запускает headless EDT. Код 0 - проекты готовы, 1 - EDT не запущена или завершилась, 2 - срок истек, а EDT еще загружается.

```bash
usage: edt-bridge-mcp wait-ready [-h] [--project NAME] [--timeout TIMEOUT] [--interval
                                 INTERVAL] [--workspace WORKSPACE] [--edt-dir EDT_DIR]
                                 [--port PORT] [--start-timeout START_TIMEOUT]
                                 [--no-autostart] [--heap HEAP] [--vmargs OPTIONS]
                                 [--version]
```

**Параметры**

| Параметр | Описание |
|---|---|
| `-h, --help` | показать эту справку и выйти |
| `--project NAME` | проект, которого нужно дождаться; можно повторять. Без флага ожидаются все открытые проекты EDT |
| `--timeout TIMEOUT` | сколько секунд ждать (по умолчанию 3600) |
| `--interval INTERVAL` | пауза между опросами в секундах (по умолчанию 5) |
| `--workspace WORKSPACE` | рабочая область EDT для автозапуска headless |
| `--edt-dir EDT_DIR` | каталог установки EDT (папка с 1cedtcli и dropins); без флага определяется сам |
| `--port PORT` | порт моста (по умолчанию 8770) |
| `--start-timeout START_TIMEOUT` | сколько секунд ждать поднимающийся мост |
| `--no-autostart` | не поднимать headless EDT ни при каких условиях |
| `--heap HEAP` | наибольший размер кучи JVM для автозапуска headless EDT, например 4096m или 6g |
| `--vmargs OPTIONS` | другие параметры JVM для автозапуска headless EDT через пробел; присоединять к флагу знаком =, потому что они начинаются с дефиса |
| `--version` | показать версию и выйти |

## `edt-bridge-mcp shutdown`

Штатно завершить EDT, обслуживающую мост, - вместо taskkill по процессам. Headless обвязка поднимет заново при следующем вызове; GUI без `--force` не трогается.

```bash
usage: edt-bridge-mcp shutdown [-h] [--force] [--no-wait] [--workspace WORKSPACE]
                               [--edt-dir EDT_DIR] [--port PORT] [--start-timeout
                               START_TIMEOUT] [--no-autostart] [--heap HEAP] [--vmargs
                               OPTIONS] [--version]
```

**Параметры**

| Параметр | Описание |
|---|---|
| `-h, --help` | показать эту справку и выйти |
| `--force` | разрешить завершение GUI EDT; без этого флага завершение GUI запрещено |
| `--no-wait` | не ждать остановки (по умолчанию ожидание закрытия порта составляет до 60 секунд) |
| `--workspace WORKSPACE` | рабочая область EDT для автозапуска headless |
| `--edt-dir EDT_DIR` | каталог установки EDT (папка с 1cedtcli и dropins); без флага определяется сам |
| `--port PORT` | порт моста (по умолчанию 8770) |
| `--start-timeout START_TIMEOUT` | сколько секунд ждать поднимающийся мост |
| `--no-autostart` | не поднимать headless EDT ни при каких условиях |
| `--heap HEAP` | наибольший размер кучи JVM для автозапуска headless EDT, например 4096m или 6g |
| `--vmargs OPTIONS` | другие параметры JVM для автозапуска headless EDT через пробел; присоединять к флагу знаком =, потому что они начинаются с дефиса |

## `edt-bridge-mcp workspace`

Готовая рабочая область EDT: pack упаковывает рабочую область остановленной EDT в архив tar с временами изменения, restore восстанавливает ее по тому же пути, checks сохраняет замечания EDT по проектам в файл (`--output`) или сравнивает с ним (`--compare`). Журналы .metadata с командной строкой EDT в архив не попадают.

```bash
usage: edt-bridge-mcp workspace [-h] [--archive PATH] [--output PATH] [--compare PATH]
                                [--project NAME] [--object FQN] [--wait WAIT]
                                [--workspace WORKSPACE] [--edt-dir EDT_DIR] [--port
                                PORT] [--start-timeout START_TIMEOUT] [--no-autostart]
                                [--heap HEAP] [--vmargs OPTIONS] [--version]
                                {pack,restore,checks}
```

**Аргументы**

| Параметр | Описание |
|---|---|
| `{pack,restore,checks}` | действие: pack, restore или checks |

**Параметры**

| Параметр | Описание |
|---|---|
| `-h, --help` | показать эту справку и выйти |
| `--archive PATH` | архив рабочей области: .tar, .tar.gz или .tar.zst (Python 3.14 и новее) |
| `--output PATH` | checks: новый файл для сохранения замечаний |
| `--compare PATH` | checks: файл сохраненных замечаний для сравнения; код 2, если замечания различаются |
| `--project NAME` | checks: проект для проверки; можно повторять. Без флага проверяются все открытые проекты EDT |
| `--object FQN` | checks: объект метаданных, замечания которого сравниваются, например Document.Order; можно повторять. Без флага проверяется проект целиком, что на большой конфигурации упирается в предел числа замечаний |
| `--wait WAIT` | checks: сколько секунд ждать завершения проверки каждого проекта (по умолчанию 600) |
| `--workspace WORKSPACE` | рабочая область EDT для автозапуска headless |
| `--edt-dir EDT_DIR` | каталог установки EDT (папка с 1cedtcli и dropins); без флага определяется сам |
| `--port PORT` | порт моста (по умолчанию 8770) |
| `--start-timeout START_TIMEOUT` | сколько секунд ждать поднимающийся мост |
| `--no-autostart` | не поднимать headless EDT ни при каких условиях |
| `--heap HEAP` | наибольший размер кучи JVM для автозапуска headless EDT, например 4096m или 6g |
| `--vmargs OPTIONS` | другие параметры JVM для автозапуска headless EDT через пробел; присоединять к флагу знаком =, потому что они начинаются с дефиса |
| `--version` | показать версию и выйти |

## `edt-bridge-mcp test-form`

В изолированном Linux проверить форму EPF, ERF или объекта конфигурации в явно выбранной файловой тестовой базе.

```bash
usage: edt-bridge-mcp test-form [-h] --platform-bin PLATFORM_BIN --test-infobase
                                TEST_INFOBASE --scope {empty,fixture,application} (--epf
                                EPF | --erf ERF | --navigation-link NAVIGATION_LINK)
                                --form FORM [--form-title FORM_TITLE] (--button BUTTON |
                                --scenario SCENARIO) [--expect-message EXPECT_MESSAGE]
                                [--user USER] --output-dir OUTPUT_DIR [--timeout
                                TIMEOUT] [--version]
```

**Параметры**

| Параметр | Описание |
|---|---|
| `-h, --help` | показать эту справку и выйти |
| `--platform-bin PLATFORM_BIN` | каталог платформы с исполняемыми файлами 1cv8 и ibcmd |
| `--test-infobase TEST_INFOBASE` | каталог выделенной файловой тестовой базы с файлом 1Cv8.1CD |
| `--scope {empty,fixture,application}` | область проверки: пустая база (empty), контрольная конфигурация (fixture) или прикладное окружение (application) |
| `--epf EPF` | файл проверяемой внешней обработки |
| `--erf ERF` | файл проверяемого внешнего отчета |
| `--navigation-link NAVIGATION_LINK` | внутренняя ссылка e1cib/data на документ или элемент справочника в тестовой базе |
| `--form FORM` | полное имя управляемой формы, например ExternalReport.Sales.Form для штатной формы СКД |
| `--form-title FORM_TITLE` | заголовок окна формы в клиенте; * и ? – знаки подстановки. Окно формы объекта дописывает к заголовку представление объекта, поэтому передавать шаблон вида "Заголовок*". Без флага форма ищется по имени из `--form` |
| `--button BUTTON` | точный заголовок кнопки, выполняющей команду |
| `--scenario SCENARIO` | файл JSON со сценарием ввода, команд и проверок наблюдаемого результата |
| `--expect-message EXPECT_MESSAGE` | точное новое сообщение после команды для подтверждения результата |
| `--user USER` | имя пользователя тестовой базы, если оно необходимо для входа без пароля |
| `--output-dir OUTPUT_DIR` | новый каталог для отчета JSON и снимка PNG; недостающие родительские каталоги создаются |
| `--timeout TIMEOUT` | предел времени проверки в секундах, по умолчанию 120 |
| `--version` | показать версию и выйти |

Запускайте проверку в изолированном Linux-окружении с `1cv8`, `ibcmd`, `Xvfb` и `libX11`. Укажите одноразовую файловую базу и одну цель: `--epf`, `--erf` или `--navigation-link`. Для EPF и ERF с назначенной формой укажите ее полное имя. Для ERF с основной СКД и без назначенной формы используйте `ExternalReport.<Имя>.Form`. Для объекта конфигурации обязателен `--scenario`.

JSON-сценарий проверяет фактические поля, ячейки табличного документа и число новых сообщений. Фаза `reopen` открывает ту же цель в новой сессии для чтения сохраненного состояния. Команда записывает `result.json`, снимок каждой фазы, когда доступен экран клиента, и отчеты для CI `junit.xml` и `allure-results/`. Настройка защиты от опасных действий остается за владельцем тестового окружения; CLI ее не меняет.

В профиле `--button` успех требует `--expect-message`; без него результат `command_observed` возвращает код **2**. Предел времени включает подготовку и все фазы; завершение процессов имеет отдельный короткий срок. Подготовка, формат сценария и примеры приведены в [руководстве по проверке форм](/ru/native-forms).

## `edt-bridge-mcp unit-tests`

В изолированном Linux загрузить собранные расширения в копию файловой тестовой базы и выполнить их тесты YAXUnit.

```bash
usage: edt-bridge-mcp unit-tests [-h] --platform-bin PLATFORM_BIN --test-infobase
                                 TEST_INFOBASE --extension NAME=PATH [--module MODULE]
                                 [--test MODULE.TEST[.CONTEXT]] [--user USER]
                                 --output-dir OUTPUT_DIR [--timeout TIMEOUT] [--version]
```

**Параметры**

| Параметр | Описание |
|---|---|
| `-h, --help` | показать эту справку и выйти |
| `--platform-bin PLATFORM_BIN` | каталог платформы с исполняемыми файлами 1cv8 и ibcmd |
| `--test-infobase TEST_INFOBASE` | каталог файловой тестовой базы с расширением YAXUNIT; сама база не меняется, тесты идут в ее копии |
| `--extension NAME=PATH` | расширение для загрузки в копию: имя расширения в проекте и путь к .cfe; можно повторять |
| `--module MODULE` | выполнить только тесты этого модуля; можно повторять |
| `--test MODULE.TEST[.CONTEXT]` | выполнить только этот тест: Модуль.Тест или Модуль.Тест.Контекст; можно повторять |
| `--user USER` | пользователь тестовой базы для ibcmd и клиента |
| `--output-dir OUTPUT_DIR` | новый каталог для отчета JSON, отчета jUnit и лога YAXUnit; недостающие родительские каталоги создаются |
| `--timeout TIMEOUT` | предел времени запуска в секундах, по умолчанию 300 |
| `--version` | показать версию и выйти |

Запускайте команду в том же изолированном Linux-окружении, что и `test-form`. В тестовой базе заранее должен быть загружен YAXUnit (расширение `YAXUNIT`). Команда копирует `1Cv8.1CD` базы, загружает в копию расширения `--extension` и выполняет их тесты, сама база не меняется. `NAME` – имя расширения в его проекте.

Команда записывает `result.json`, отчеты `junit.xml` и `allure-results/` и лог `yaxunit.log`. Успех – хотя бы один выполненный тест и ни одного упавшего; иначе код **2**. Подготовка базы и поля результата описаны на странице [тестов YAXUnit](/ru/native-forms/unit-tests).

## `edt-bridge-mcp self-update`

Обновить jar плагина в dropins EDT, обвязку в ее окружении и плагины обвязки.

```bash
usage: edt-bridge-mcp self-update [-h] [--jar-only | --pip-only | --plugins-only]
                                  [--from PATH | --version X.Y.Z] [--workspace
                                  WORKSPACE] [--edt-dir EDT_DIR] [--port PORT]
                                  [--start-timeout START_TIMEOUT] [--no-autostart]
                                  [--heap HEAP] [--vmargs OPTIONS]
```

**Параметры**

| Параметр | Описание |
|---|---|
| `-h, --help` | показать эту справку и выйти |
| `--jar-only` | обновить только jar плагина |
| `--pip-only` | обновить только обвязку |
| `--plugins-only` | обновить только плагины обвязки |
| `--from PATH` | установить обвязку из рабочей копии |
| `--version X.Y.Z` | установить указанную версию jar и обвязки или одного из них по выбранному режиму |
| `--workspace WORKSPACE` | рабочая область EDT для автозапуска headless |
| `--edt-dir EDT_DIR` | каталог установки EDT (папка с 1cedtcli и dropins); без флага определяется сам |
| `--port PORT` | порт моста (по умолчанию 8770) |
| `--start-timeout START_TIMEOUT` | сколько секунд ждать поднимающийся мост |
| `--no-autostart` | не поднимать headless EDT ни при каких условиях |
| `--heap HEAP` | наибольший размер кучи JVM для автозапуска headless EDT, например 4096m или 6g |
| `--vmargs OPTIONS` | другие параметры JVM для автозапуска headless EDT через пробел; присоединять к флагу знаком =, потому что они начинаются с дефиса |

С параметром `--version` команда берет jar по тегу vX.Y.Z на GitHub и обвязку с PyPI. Параметры `--version` и `--from` нельзя сочетать с `--plugins-only`. Параметр `--from` также несовместим с `--jar-only`.

После обновления перезапустите EDT для загрузки jar и клиент MCP для загрузки обвязки.

Плагины обвязки обновляются через pip из своих источников установки. Для реестра пакетов можно указать адрес в переменной EDT_BRIDGE_PLUGIN_INDEX.

Код 0 означает, что все выбранные операции выполнены. Код 1 означает, что обновление jar или обвязки не удалось либо не удалась ни одна операция. Код 2 означает ошибку аргументов или сбой только при обновлении плагинов обвязки.
