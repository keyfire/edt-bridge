Небольшой **плагин для 1C:EDT**. Он отдаёт **живую семантическую модель** среды ИИ-агентам и другим
инструментам по протоколу **MCP**.

Статический парсер читает тексты файлов. EDT-Bridge вместо этого спрашивает работающую среду,
поэтому отвечает и на то, что знает только *живая* модель: собственные диагностики EDT, настоящую
структуру и типы метаданных, семантические перекрёстные ссылки, **проверку запроса по настоящим
метаданным проекта** и **Синтакс-помощник платформы** из поставки EDT. Чтением дело не
заканчивается. Инструменты записи создают объекты, переименовывают, собирают и поставляют; рядом с
ними работа с информационными базами и отладчик. Всё это делает штатный движок EDT.

> Чтение **и** запись. Только localhost. Записи нужен токен, и пока её не попросят прямо, она
> возвращает план. Плагин работает внутри EDT, поэтому EDT – с интерфейсом или headless – должна
> быть запущена с вашим проектом.

## Установка (рекомендуется: pipx)

Одна команда ставит обе половины: обвязку клиента и плагин. Обвязка
[**edt-bridge-mcp**](https://github.com/keyfire/edt-bridge/blob/main/python/README.ru.md) – это
stdio MCP-сервер, с которым разговаривает клиент. Она пробрасывает запросы в запущенную EDT,
**поднимает headless EDT**, когда ни одна не открыта, и **сама доставляет jar плагина** в `dropins/`
EDT, если его там нет. Копировать jar руками не придётся.

```bash
pipx install edt-bridge-mcp
```

Затем зарегистрируйте её в MCP-клиенте. В примере это Claude Code, а `--workspace` – рабочая область
EDT, которую поднимать при автозапуске headless:

```bash
claude mcp add edt-bridge -- edt-bridge-mcp --workspace "D:\\путь\\к\\workspace-EDT"
```

Это вся настройка. Флаги обвязки, токен инструментов записи и `self-update` описаны в
[python/README.ru.md](https://github.com/keyfire/edt-bridge/blob/main/python/README.ru.md). Если
хотите запускать плагин сами, без обвязки, смотрите
[Установку вручную](/ru/install#установка-вручную-без-обвязки).

<details>
<summary>Нет <code>pipx</code>?</summary>

`pipx` ставит Python-приложения CLI в изолированные окружения. Установить один раз:

```bash
python -m pip install --user pipx
python -m pipx ensurepath      # затем переоткрыть терминал
```

macOS: `brew install pipx && pipx ensurepath`. Подробнее: <https://pipx.pypa.io>.
</details>

### Настройки в самой EDT

У плагина есть своя страница параметров – **Окно ▸ Параметры ▸ EDT-Bridge**. Именно оттуда берётся
токен, когда мост работает внутри EDT с интерфейсом:

| Параметр | Что это |
|----------|---------|
| **Токен для инструментов записи** | Общий секрет, который требует каждый инструмент записи. Пустой токен означает, что запись запрещена, а не что она открыта всем. Клиенту уходит то же значение под именем `EDT_BRIDGE_TOKEN`. |
| **Порт MCP-сервера** | По умолчанию 8770. **Вступает в силу после перезапуска EDT**, а до перезапуска работающий сервер держит прежний порт. |
| **Разрешить выполнение произвольного кода BSL при отладке** | По умолчанию выключено. Этот переключатель закрывает `edt_evaluate`, который исполняет код против живой информационной базы. Только тестовые стенды. |

**Параметр запуска сильнее этой страницы.** Системные свойства `-Dedt.bridge.*` и переменные
окружения `EDT_BRIDGE_*`, заданные при старте, имеют приоритет над сохранёнными значениями. Так
обвязка и управляет headless-экземпляром. По этой же причине заданный здесь токен выглядит
проигнорированным, если его передали ещё и в командной строке.

## Рядом

EDT-Bridge работает с 1С:Предприятием. У соседней платформы, 1С:Элемент, есть пара инструментов,
сделанных по тому же принципу: дать агенту руки, а не советы.

- **[XBSL](https://docs.keyfire.ru/xbsl/ru/)** – линтер исходников Элемента с автоправками, LSP-сервер,
  создание метаданных, MCP-сервер и расширение VS Code.
- **[Elemctl](https://docs.keyfire.ru/elemctl/ru/)** – доставка на стенд Элемента: сборка, загрузка,
  применение и проверка, что оно применилось.

## Страница в браузере

Откройте `http://127.0.0.1:8770/` – это встроенная страница состояния: сервер, открытые проекты EDT
и запуск любого инструмента. Есть светлая и тёмная тема и переключатель EN/RU.
