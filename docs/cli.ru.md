Обвязка `edt-bridge-mcp` работает как stdio MCP-сервер для клиента. Из командной строки можно проверить состояние моста, получить список инструментов и вызвать инструмент без запуска агента.

Без команды обвязка работает как MCP-сервер. Команды работы с мостом используют тот же экземпляр EDT. `test-form` запускает отдельные сеансы платформы.

Для вызовов инструментов код возврата **1** означает, что мост не запустился или аргументы неверны. Код **2** означает, что инструмент выполнился и вернул ошибку.

## Без команды: запуск MCP-сервера

MCP-сервер stdio для плагина edt-bridge к 1С:EDT: передает запросы в запущенную EDT и запускает headless EDT при отсутствии работающей среды.

```bash
usage: edt-bridge-mcp [опции]                   (без команды: запуск MCP-сервера)
       edt-bridge-mcp <команда> [опции]
```

**Параметры**

| Параметр | Описание |
|---|---|
| `-h, --help` | показать эту справку и выйти |
| `--workspace WORKSPACE` | рабочая область EDT для автозапуска headless |
| `--edt-dir EDT_DIR` | каталог установки EDT (папка с 1cedtcli и dropins); без флага определяется сам |
| `--port PORT` | порт моста (по умолчанию 8770) |
| `--start-timeout START_TIMEOUT` | сколько секунд ждать поднимающийся мост |
| `--no-autostart` | не поднимать headless EDT ни при каких условиях |
| `--version` | показать версию и выйти |

**Команды**

| Команда | Описание |
|---|---|
| `call <инструмент>` | вызвать один инструмент моста и напечатать ответ |
| `tools` | перечислить инструменты запущенного моста |
| `status` | состояние моста без его запуска |
| `shutdown` | штатно завершить EDT, обслуживающую мост |
| `gui` | остановить headless и открыть клиентскую EDT |
| `plugins` | перечислить плагины обвязки и их инструменты |
| `test-form` | проверить форму и результат сценария в тестовой базе |
| `self-update` | обновить jar плагина и саму обвязку |

Опции команды: edt-bridge-mcp &lt;команда&gt; `--help`. Опции подключения относятся к серверу MCP и командам работы с мостом.

## `edt-bridge-mcp call`

Вызвать один инструмент моста и напечатать результат.

```bash
usage: edt-bridge-mcp call [-h] [--json JSON | --json-file PATH | --stdin] [--raw]
                           [--workspace WORKSPACE] [--edt-dir EDT_DIR] [--port PORT]
                           [--start-timeout START_TIMEOUT] [--no-autostart] [--version]
                           tool
```

**Аргументы**

| Параметр | Описание |
|---|---|
| `tool` | имя инструмента, например edt_projects (перечень: edt-bridge-mcp tools) |

**Параметры**

| Параметр | Описание |
|---|---|
| `-h, --help` | показать эту справку и выйти |
| `--json JSON` | аргументы инструмента объектом JSON |
| `--json-file PATH` | читать объект JSON из файла в UTF-8; этот способ подходит для аргументов с неанглийским текстом на Windows |
| `--stdin` | читать объект JSON из потока ввода |
| `--raw` | напечатать сырой JSON-результат вместо текста, который вернул инструмент |
| `--workspace WORKSPACE` | рабочая область EDT для автозапуска headless |
| `--edt-dir EDT_DIR` | каталог установки EDT (папка с 1cedtcli и dropins); без флага определяется сам |
| `--port PORT` | порт моста (по умолчанию 8770) |
| `--start-timeout START_TIMEOUT` | сколько секунд ждать поднимающийся мост |
| `--no-autostart` | не поднимать headless EDT ни при каких условиях |
| `--version` | показать версию и выйти |

Аргументы инструмента принимаются из `--json`, файла (`--json-file`) или потока ввода (`--stdin`). На Windows передавать кириллицу в файле: консольная кодировка может исказить аргументы командной строки.

## `edt-bridge-mcp status`

Состояние запущенного моста и версия JAR в dropins. Команда сообщает в stderr о расхождении версий обвязки и плагина. С `--all` она проверяет каждый найденный мост.

```bash
usage: edt-bridge-mcp status [-h] [--all] [--ports PORTS] [--workspace WORKSPACE]
                             [--edt-dir EDT_DIR] [--port PORT] [--start-timeout
                             START_TIMEOUT] [--no-autostart] [--version]
```

**Параметры**

| Параметр | Описание |
|---|---|
| `-h, --help` | показать эту справку и выйти |
| `--all` | проверить все порты диапазона без фильтра рабочей области и запуска EDT |
| `--ports PORTS` | порты для `--all`, через запятую или диапазон: 8770,8772-8774 (до 128 портов) |
| `--workspace WORKSPACE` | рабочая область EDT для автозапуска headless |
| `--edt-dir EDT_DIR` | каталог установки EDT (папка с 1cedtcli и dropins); без флага определяется сам |
| `--port PORT` | порт моста (по умолчанию 8770) |
| `--start-timeout START_TIMEOUT` | сколько секунд ждать поднимающийся мост |
| `--no-autostart` | не поднимать headless EDT ни при каких условиях |
| `--version` | показать версию и выйти |

## `edt-bridge-mcp shutdown`

Штатно завершить EDT, обслуживающую мост, - вместо taskkill по процессам. Headless обвязка поднимет заново при следующем вызове; GUI без `--force` не трогается.

```bash
usage: edt-bridge-mcp shutdown [-h] [--force] [--no-wait] [--workspace WORKSPACE]
                               [--edt-dir EDT_DIR] [--port PORT] [--start-timeout
                               START_TIMEOUT] [--no-autostart] [--version]
```

**Параметры**

| Параметр | Описание |
|---|---|
| `-h, --help` | показать эту справку и выйти |
| `--force` | разрешить завершение GUI EDT; без этого флага завершение GUI запрещено |
| `--no-wait` | не ждать остановки (по умолчанию ожидание закрытия порта составляет до 60 секунд) |
| `--workspace WORKSPACE` | рабочая область EDT для автозапуска headless |
| `--edt-dir EDT_DIR` | каталог установки EDT (папка с 1cedtcli и dropins); без флага определяется сам |
| `--port PORT` | порт моста (по умолчанию 8770) |
| `--start-timeout START_TIMEOUT` | сколько секунд ждать поднимающийся мост |
| `--no-autostart` | не поднимать headless EDT ни при каких условиях |
| `--version` | показать версию и выйти |

## `edt-bridge-mcp gui`

Передать рабочую область клиентской EDT: остановить headless, дождаться, пока его процессы действительно исчезнут, и запустить окно EDT на той же рабочей области. Обвязка не запускает headless EDT при выполнении команды.

```bash
usage: edt-bridge-mcp gui [-h] [--force] [--timeout TIMEOUT] [--workspace WORKSPACE]
                          [--edt-dir EDT_DIR] [--port PORT] [--start-timeout
                          START_TIMEOUT] [--no-autostart] [--version]
```

**Параметры**

| Параметр | Описание |
|---|---|
| `-h, --help` | показать эту справку и выйти |
| `--force` | завершить headless принудительно, если он не остановился за отведенное время |
| `--timeout TIMEOUT` | сколько секунд ждать завершения headless (по умолчанию 90) |
| `--workspace WORKSPACE` | рабочая область EDT для автозапуска headless |
| `--edt-dir EDT_DIR` | каталог установки EDT (папка с 1cedtcli и dropins); без флага определяется сам |
| `--port PORT` | порт моста (по умолчанию 8770) |
| `--start-timeout START_TIMEOUT` | сколько секунд ждать поднимающийся мост |
| `--no-autostart` | не поднимать headless EDT ни при каких условиях |
| `--version` | показать версию и выйти |

## `edt-bridge-mcp test-form`

В изолированном Linux проверить форму EPF, ERF или объекта конфигурации в явно выбранной файловой тестовой базе.

```bash
usage: edt-bridge-mcp test-form [-h] --platform-bin PLATFORM_BIN --test-infobase
                                TEST_INFOBASE --scope {empty,fixture,application} (--epf
                                EPF | --erf ERF | --navigation-link NAVIGATION_LINK)
                                --form FORM --form-title FORM_TITLE (--button BUTTON |
                                --scenario SCENARIO) [--expect-message EXPECT_MESSAGE]
                                [--user USER] --output-dir OUTPUT_DIR [--timeout
                                TIMEOUT] [--version]
```

**Параметры**

| Параметр | Описание |
|---|---|
| `-h, --help` | показать эту справку и выйти |
| `--platform-bin PLATFORM_BIN` | каталог платформы с исполняемыми файлами 1cv8 и ibcmd |
| `--test-infobase TEST_INFOBASE` | каталог выделенной файловой тестовой базы с файлом 1Cv8.1CD |
| `--scope {empty,fixture,application}` | область проверки: пустая база (empty), контрольная конфигурация (fixture) или прикладное окружение (application) |
| `--epf EPF` | файл проверяемой внешней обработки |
| `--erf ERF` | файл проверяемого внешнего отчета |
| `--navigation-link NAVIGATION_LINK` | внутренняя ссылка e1cib/data на документ или элемент справочника в тестовой базе |
| `--form FORM` | полное имя управляемой формы; для EPF/ERF требуется основная форма |
| `--form-title FORM_TITLE` | точный заголовок формы в клиенте |
| `--button BUTTON` | точный заголовок кнопки, выполняющей команду |
| `--scenario SCENARIO` | файл JSON со сценарием ввода, команд и проверок наблюдаемого результата |
| `--expect-message EXPECT_MESSAGE` | точное новое сообщение после команды для подтверждения результата |
| `--user USER` | имя пользователя тестовой базы, если оно необходимо для входа без пароля |
| `--output-dir OUTPUT_DIR` | новый каталог для отчета JSON и снимка PNG |
| `--timeout TIMEOUT` | предел времени проверки в секундах, по умолчанию 120 |
| `--version` | показать версию и выйти |

Запускайте проверку в изолированном Linux-окружении с `1cv8`, `ibcmd`, `Xvfb` и `libX11`. Укажите одноразовую файловую базу и одну цель: `--epf`, `--erf` или `--navigation-link`. Для внешнего файла нужна его основная управляемая форма; для объекта конфигурации обязателен `--scenario`.

JSON-сценарий проверяет фактические поля, ячейки табличного документа и число новых сообщений. Фаза `reopen` открывает ту же цель в новой сессии для чтения сохраненного состояния. Команда записывает `result.json` и снимок каждой фазы, когда доступен экран клиента. Настройка защиты от опасных действий остается за владельцем тестового окружения; CLI ее не меняет.

В профиле `--button` успех требует `--expect-message`; без него результат `command_observed` возвращает код **2**. Предел времени включает подготовку и все фазы; завершение процессов имеет отдельный короткий срок. Подготовка, формат сценария и примеры приведены в [руководстве по проверке форм](native-forms.ru.md).

## `edt-bridge-mcp self-update`

Обновить jar плагина в dropins EDT, обвязку в ее окружении и плагины обвязки.

```bash
usage: edt-bridge-mcp self-update [-h] [--jar-only | --pip-only | --plugins-only]
                                  [--from PATH | --version X.Y.Z] [--workspace
                                  WORKSPACE] [--edt-dir EDT_DIR] [--port PORT]
                                  [--start-timeout START_TIMEOUT] [--no-autostart]
```

**Параметры**

| Параметр | Описание |
|---|---|
| `-h, --help` | показать эту справку и выйти |
| `--jar-only` | обновить только jar плагина |
| `--pip-only` | обновить только обвязку |
| `--plugins-only` | обновить только плагины обвязки |
| `--from PATH` | установить обвязку из рабочей копии |
| `--version X.Y.Z` | установить указанную версию jar и обвязки или одного из них по выбранному режиму |
| `--workspace WORKSPACE` | рабочая область EDT для автозапуска headless |
| `--edt-dir EDT_DIR` | каталог установки EDT (папка с 1cedtcli и dropins); без флага определяется сам |
| `--port PORT` | порт моста (по умолчанию 8770) |
| `--start-timeout START_TIMEOUT` | сколько секунд ждать поднимающийся мост |
| `--no-autostart` | не поднимать headless EDT ни при каких условиях |

С параметром `--version` команда берет jar по тегу vX.Y.Z на GitHub и обвязку с PyPI. Параметры `--version` и `--from` нельзя сочетать с `--plugins-only`. Параметр `--from` также несовместим с `--jar-only`.

После обновления перезапустите EDT для загрузки jar и клиент MCP для загрузки обвязки.

Плагины обвязки обновляются через pip из своих источников установки. Для реестра пакетов можно указать адрес в переменной EDT_BRIDGE_PLUGIN_INDEX.

Код 0 означает, что все выбранные операции выполнены. Код 1 означает, что обновление jar или обвязки не удалось либо не удалась ни одна операция. Код 2 означает ошибку аргументов или сбой только при обновлении плагинов обвязки.
